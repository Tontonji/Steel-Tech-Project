# Steel Drawing → BOQ (Gemini Vision research MVP)

A single-page Streamlit tool for an undergraduate research project: how accurately can a
multimodal LLM (Gemini) extract steel member data from a CAD-exported structural drawing PDF
and produce a bill of quantities, compared with manual takeoff?

**One PDF in, one editable table out, one local log per run.** Nothing is stored beyond the
session except the JSON logs on your own disk.

## Scope and non-goals

- CAD-exported PDFs only (vector text). Scanned or hand-drawn sheets are out of scope.
- Member schedules and framing plans only. No connection details, no bolts/plates.
- No login, no database, no project history, no telemetry.

## Quickstart

```powershell
cd steel_boq_mvp
python -m venv .venv            # Python 3.11+ (tested on 3.14)
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env          # then put your Gemini key in .env
streamlit run app.py
```

Tip: if this folder lives in OneDrive, a venv outside it is faster, e.g.
`python -m venv $env:LOCALAPPDATA\venvs\steel_boq`.

`.env` keys:

| Key | Purpose |
|---|---|
| `GEMINI_API_KEY` | required; never commit it |
| `GEMINI_MODEL` | optional, default `gemini-2.5-flash` (try `gemini-2.5-pro` for harder sheets) |

## How it works

```
PDF ─► PyMuPDF renders selected pages to PNG (200–300 DPI)
    ─► Gemini (google-genai, JSON mode, temperature 0) with the extraction prompt
    ─► defensive JSON parse ─► pandas DataFrame (+ approximate unit weight)
    ─► st.data_editor (correct the AI inline) ─► Excel download
    └─► logs/{timestamp}.json (raw response, parsed rows, latency)
```

Files:

| File | Role |
|---|---|
| `app.py` | Streamlit UI. The only module that imports Streamlit. |
| `pdf_utils.py` | Open/validate PDF, page count, page and thumbnail rendering. |
| `gemini_client.py` | The prompt, the API call, and JSON parsing. All SDK use is inside `call_gemini`. |
| `boq_utils.py` | Rows → DataFrame, unit-weight lookup, summary, Excel bytes, export filename. |
| `research_log.py` | Writes the per-run JSON log. |
| `score.py` | CLI to score a run against a ground-truth CSV. |
| `samples/make_sample.py` | Generates the synthetic 3-page sample drawing and its ground truth. |

## The extraction prompt

Sent verbatim after the page images (see `gemini_client.PROMPT`):

```
You are reading a structural steel drawing (framing plan or member schedule).
Extract every distinct steel member you can identify. For each member, return:
- member_id: the label/tag shown on the drawing (e.g. B1, C2, GB-01)
- section: the section designation (e.g. H-300x300x10x15, W12x26)
- length_mm: member length in millimeters if shown or derivable from dimensions
- quantity: number of instances of this member type
- notes: anything ambiguous, illegible, or inferred rather than directly read

Return ONLY a JSON array of objects with these exact keys. No prose, no markdown
fences, no explanation. If a value cannot be determined, use null for that field
and explain briefly in notes.
```

## Output columns

| Column | Source |
|---|---|
| `member_id`, `section`, `length_mm`, `quantity`, `notes` | straight from the model (coerced to str / float / int, `null` → blank) |
| `unit_weight_kg_m` | derived locally, not from the model. H/I and channel designations `h×b×tw×tf` use 7850 kg/m³ × (2·b·tf + (h−2·tf)·tw), ignoring root fillets (about 1–2 % low). A few JIS channels come from a small table. `W12x26`-style shapes convert lb/ft × 1.488. Angles, plates and anything unparsable are left blank. |

The summary shows distinct member IDs, total quantity, and total weight over rows where
quantity, length and unit weight are all present.

The Excel file `boq_{original_name}_{YYYYMMDD_HHMMSS}.xlsx` has a `BOQ` sheet (the edited table)
and a `Summary` sheet. The timestamp matches the log file for the same run.

## Research logs

Every click of **Extract** writes `logs/YYYYMMDD_HHMMSS.json` (also on failure):

```json
{
  "timestamp": "2026-09-08T12:00:00",
  "app_version": "0.1.0",
  "source_filename": "sample_schedule.pdf",
  "model": "gemini-2.5-flash",
  "pages": [0, 1],
  "dpi": 220,
  "latency_s": 6.42,
  "error": null,
  "raw_response": "[{...}]",
  "parsed_rows": [{"member_id": "B1", "section": "H-300x150x6.5x9", "length_mm": 6000.0, "quantity": 8, "notes": null}]
}
```

`latency_s` is measured from just before the API call to just after parsing. Editing the table
or downloading never re-runs extraction, so one log equals one model call.

## Sample drawing and scoring

`samples/sample_schedule.pdf` is a deterministic synthetic drawing generated by
`python samples/make_sample.py`:

1. **S-201 member schedule**: 12 rows including a null length (`CH-2`), an angle with no unit weight
   (`BR-1`), an imperial W-shape (`P1`), a length marked `SEE PLAN` (`B4`), and a deliberately faint
   6 pt row (`X1`).
2. **S-101 framing plan**: grid with dimension strings; gives `B4` its 7000 mm span and shows a
   plan-only tag `B5` that is not in the schedule.
3. **S-001 general notes**: no members (hallucination check).

`samples/ground_truth.csv` lists all 13 expected members. Score a run with:

```powershell
python score.py --pred logs\20260908_120000.json --truth samples\ground_truth.csv
# or the exported spreadsheet
python score.py --pred boq_sample_schedule_20260908_120000.xlsx --truth samples\ground_truth.csv
```

It reports precision / recall / F1 on member IDs plus section, length and quantity accuracy over
matched IDs, and lists missed and spurious IDs. IDs are matched case-insensitively ignoring
spaces; sections ignore spaces, `×` vs `x`, and a leading `H-`.

For real drawings, build the ground truth by manual takeoff into a CSV with the same columns and
score the same way.

## Tests

```powershell
python -m pytest -q
```

Runs offline. The Gemini client is faked; PDF rendering, parsing, Excel export, logging, scoring
and the Streamlit script (via `streamlit.testing`) all run for real.

## Known limitations

- The synthetic sample uses perfectly rendered text, so scores on it are optimistic. Real
  CAD exports vary in font, layer colour and table style.
- Unit weights are approximations for comparison, not for fabrication ordering.
- Very large sheets are capped at 10 pages per call; the DPI slider trades legibility for payload size.
